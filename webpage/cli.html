⌨️ mm: Money Manager on the command line

Query accounts, balances and transactions and run every import from a terminal or a script. mm opens the same database files as the desktop app and shares its settings, so you can use both on the same database.

Install

Standalone binary

Every release attaches a native mm for each platform. It's a single file and needs no Java:

PlatformRelease asset
Linux x64mm-linux-x64.tar.gz
Linux ARM64mm-linux-arm64.tar.gz
macOS (Apple silicon)mm-macos-arm64.tar.gz
Windows x64mm-windows-x64.exe

Linux and macOS: the tarball holds an executable mm. Put it on your PATH:

tar -xzf mm-linux-x64.tar.gz
install -m 755 mm ~/.local/bin/mm
mm version

The macOS binary isn't signed. If Gatekeeper blocks it, clear the quarantine flag: xattr -d com.apple.quarantine mm.

Windows: rename mm-windows-x64.exe to mm.exe and put it in a folder on your PATH.

With the desktop app

The desktop installers ship the CLI as well. mm-jvm is a launcher that runs on the app's bundled Java runtime. The host's native mm is installed alongside it:

Installermm-jvmnative mm
Linux (.deb)/opt/moneymanager/bin/mm-jvm/opt/moneymanager/lib/cli/mm
macOS (.dmg)MoneyManager.app/Contents/MacOS/mm-jvmMoneyManager.app/Contents/cli/mm
Windows (.msi)mm-jvm.exe in the install foldercli\mm.exe in the install folder

Both builds behave the same. The native one starts faster.

From source

# Native binary for this machine (Linux x64 shown; also LinuxArm64, MacosArm64, MingwX64)
./gradlew :app:main:cli:linkReleaseExecutableLinuxX64 --console=plain
app/main/cli/build/bin/linuxX64/releaseExecutable/mm.kexe version

# JVM build, a quicker way to try a change
./gradlew :app:main:cli:installJvmDist --console=plain
app/main/cli/build/install/mm-jvm-jvm/bin/mm-jvm version

Databases

With no --db, mm opens the database that the desktop app or mm last opened. Both keep it in ~/.moneymanager/settings.json. Pass --db PATH to choose a different file. mm opens existing databases only. Create a new one in the desktop app.

Cloud-backed databases (Google Drive) open from the local working copy the desktop app keeps, so opening one needs no password and no network. Two things change that:

  • --hydrate downloads the cloud copy first.
  • When the cloud password is available (MM_REMOTE_PASSWORD, or a prompt in a terminal), mm checks the remote. If another device has changes you haven't downloaded, writes are refused (exit 1) until you rerun with --hydrate.

On exit, if a command changed a cloud-backed database, mm asks whether to upload it and whether to keep the local copy, just like the desktop app's close dialog. In scripts, answer up front with --push/--no-push and --keep-local/--drop-local. A refused or failed upload exits 3.

Credential vault

API tokens and Google sign-ins live in the encrypted, password-protected credential vault, not in the database. mm unlocks it only when a command needs a secret, such as import apis or a Google Drive import folder. It takes the password from the first of these that is available:

  1. --vault-password-stdin: the first line of stdin;
  2. the MM_VAULT_PASSWORD environment variable;
  3. a no-echo prompt, in a terminal.

If none of these is available, the command fails with exit 1. If the database has no vault yet, mm offers to create one at the default path (only in a terminal). mm never stores the password. 

# From a password manager
pass show money-manager/vault | mm --vault-password-stdin import apis

# From the environment, e.g. in a scheduled job
MM_VAULT_PASSWORD="$(secret-tool lookup app mm-vault)" mm --push import all

Google sign-in over SSH. The first time a Google Drive folder needs a sign-in, mm opens the consent page in a browser. With --no-browser it prints the URL instead and waits for the redirect on a loopback port. On a remote machine, forward that port and open the URL locally: 

ssh -L <port>:localhost:<port> my-server
mm --no-browser import dirs

Global options

Global options go before the command: mm --db ~/finance.db --format json accounts.

OptionMeaning
--db PATHDatabase file. Default: the last one the desktop app or mm opened
--format json|tableOutput format. Default: a table in a terminal, JSON when stdout is redirected
-q, --quietPrint only the result and errors (no progress, no warnings)
-v, --verboseAlso print debug logs to stderr
--vault-password-stdinRead the vault password from the first line of stdin
--no-browserPrint the Google sign-in URL instead of opening a browser
--hydrateCloud database: download the cloud copy before running
--push / --no-pushCloud database: upload changes on exit, or don't (default: ask in a terminal)
--keep-local / --drop-localCloud database: keep the local working copy on exit (default), or delete it

stdout carries only the result. Prompts, warnings, errors and progress go to stderr, so you can pipe the output straight into jq. Info-level logs and above go to ~/.moneymanager/logs/mm.log. Progress shows as live bars in a terminal and as plain lines when stderr isn't a terminal, NO_COLOR is set or TERM=dumb. Every command takes --help.

Commands

version, status

version prints the app version. status shows the open database, its cloud sync state and whether the credential vault is unbound, missing, locked or unlocked. 

mm status

accounts

mm accounts [--owner NAME|ID]… [--account REGEX] [--include-shadow]

Lists accounts with their owners and balances in every asset.

mm accounts --owner "Alice Smith"
mm accounts --account 'monzo|starling'

balances

mm balances [--owner NAME|ID]… [--account REGEX] [--asset CODE]… [--include-shadow] [--non-zero]

One row per account and asset. Balances are brought up to date before they're read.

mm balances --asset GBP --non-zero
mm balances --asset BTC --asset ETH --owner 1

# Tab-separated account and amount, for a spreadsheet
mm balances --asset GBP --non-zero | jq -r '.data[] | "\(.account)\t\(.amount)"'

Filters work the same way in accounts and balances. --owner matches a person's full name, ignoring case, or takes their id. --account is a case-insensitive regular expression that can match anywhere in the account name. Different filters combine with AND, and repeated values of one filter combine with OR. Shadow accounts (a reconciliation source's copy, such as Koinly's) are left out unless you pass --include-shadow.

transactions

mm transactions --account REGEX|ID [--from DATE] [--to DATE] [--limit N] [--cursor C] [--include-shadow]

One account's transactions, newest first, with the running balance after each one. --account must resolve to exactly one account: an id, or a pattern matching one name. If several names match and one of them is an exact match, the exact match wins.

  • --from and --to take YYYY-MM-DD (local time) or an ISO-8601 instant.
  • --from is inclusive.
  • --to includes that whole day when given a date, and is exclusive when given an instant.
mm transactions --account Current --from 2024-03-01 --to 2024-03-31

# Page through everything: pass nextCursor back, with the same --account and --from
page=$(mm transactions --account 7 --limit 500)
cursor=$(jq -r '.nextCursor // empty' <<<"$page")
mm transactions --account 7 --limit 500 --cursor "$cursor"

people, strategies, import-dirs

mm people · mm strategies [--kind csv|api] · mm import-dirs

people lists the full names that --owner takes. strategies lists the installed CSV and API import strategies. import-dirs lists the configured import folders, how many files have been downloaded from each and how many of those were imported. 

mm strategies --kind api
mm --format table import-dirs

import dirs, import apis, import all

mm import dirs [--dir NAME]… [--download-only] [--redownload]
mm import apis [--strategy NAME]… [--force-full] [--download-only]
mm import all [--force-full] [--download-only]

These commands download and import, using the same services as the desktop app's import screens.

  • import dirs downloads every included import folder (local and Google Drive), or only the --dir folders and their subfolders. It then imports every new CSV and QIF file. --redownload first re-downloads the files that were already downloaded.
  • import apis downloads every API connection that has secrets in the vault, all at once, or only the --strategy ones. It then imports the new sessions. --force-full downloads everything again, not just what's new.
  • import all does both at once.

Live progress goes to stderr, and the summary goes to stdout. mm never guesses. Anything only a person can resolve, such as a file no strategy matches, a folder with no source account, counterparties to confirm or an unassigned card, is listed under needsAttention and exits 3. 

# Nightly: import everything, upload the cloud copy, fail loudly on anything to resolve
MM_VAULT_PASSWORD=… mm --quiet --push --keep-local import all
[ $? -eq 3 ] && echo "Money Manager needs attention"

# What needs a person?
mm import dirs | jq '.data.needsAttention'

tui

mm [--db PATH] [--hydrate] [--push|--no-push] [--keep-local|--drop-local] tui

tui opens a full-screen terminal UI. It opens databases the same way every other command does, from --db, the cloud copy or the last database. When there's none to open, it asks for a path, and it creates a new database if no file exists there. It asks for the vault password, and on exit whether to upload a changed cloud copy, in dialogs. MM_VAULT_PASSWORD and MM_REMOTE_PASSWORD still answer without asking. It needs a terminal, so it exits 2 when stdin or stdout is redirected or with --vault-password-stdin. Logs go only to the log file while it runs.

KeyDoes
Tab → ←, 1…9Switch tabs
oOpen or create another database
?Show every key, including the current tab's own
EscDismiss a message, or cancel a dialog
q, Ctrl-CQuit after closing the database (a second Ctrl-C quits at once and exits 130)

The Accounts tab lists accounts with their owners and per-asset balances, keeps the same accounts as the desktop Accounts screen for the same filter, and follows the database as it changes, for example while an import runs. Press / to type a name filter (Enter or Esc to stop), r to switch it between plain text and a regex, p to pick owners and a to pick assets (type to narrow the list, Space to tick, Ctrl-A for any, Enter to apply), s to show reconciliation (shadow) accounts, z to show only non-zero balances, g to group the list by owner (a joint account is listed under each owner, and accounts nobody owns come last), and ↑ ↓ PgUp PgDn to move. Enter on an account opens it in the Transactions tab.

The Transactions tab lists one account's transactions, newest first, with the running balance after each. Older and newer rows load as ↑ ↓ PgUp PgDn reach either end; Home goes back to the newest row and End to the last one loaded. Press a to pick the account, f to keep a date range (from and to, both included; leave either blank for an open end), x to clear it, g to go to a date, and r to refresh the balances and reload. Dates are written as for --from/--to: YYYY-MM-DD in local time, or an ISO-8601 instant. Enter shows the selected row's detail: what moved between which accounts, its attributes, the transfers linked to it (fee, pass-through, reconciled, …) and where each revision came from. In the detail, n highlights the next linked transfer and l goes to it, opening its account when it isn't this one. The tab is read-only.

Keys outside ASCII, such as é or £, can't be typed into the TUI's prompts yet, and a paste of more than about 64 characters at once can lose some of them. Use the environment variables for passwords that contain such keys, and --db for a long database path.

JSON output

mm prints JSON when stdout isn't a terminal, or when you pass --format json. Every command prints one envelope: 

{
    "schemaVersion": 1,
    "data": [
        {
            "id": 3,
            "name": "Wallet",
            "openingDate": "2024-01-01T00:00:00Z",
            "categoryId": -1,
            "shadow": false,
            "owners": [{ "id": 1, "name": "Alice Smith" }],
            "balances": [
                { "asset": "BTC", "kind": "crypto", "amount": "0.00012345" },
                { "asset": "GBP", "kind": "currency", "amount": "100" }
            ]
        }
    ]
}
  • data is the result: an object for version, status and the import commands, and an array for the queries.
  • nextCursor appears only when another page follows (only transactions pages).
  • Amounts are exact decimal strings such as "-12.5", never JSON numbers, which would round.
  • Times are ISO-8601 instants in UTC.
  • Ids: accounts, people and transactions have integer ids. Strategies and import folders have UUIDs. A strategy's id differs between databases, so match strategies by name.
  • Versioning: schemaVersion changes only when a field is renamed or removed, or its meaning changes. New fields can appear at any time, so ignore fields you don't know.

Every command's fields are documented in the JSON contract, docs/cli-json.md. Golden tests check it, so scripts can rely on it.

Exit codes

CodeMeaning
0OK
1Error: the command failed (e.g. a locked vault with no password, writes refused on a stale cloud copy)
2Usage error: a bad option, no database, or an unknown or ambiguous name (the message lists the candidates with their ids)
3Partial failure or needs attention: some folder, file, connection or session failed, something is listed under needsAttention, or a cloud upload was refused. The summary is printed anyway
130Interrupted: the first Ctrl-C cancels the running tasks and prints the summary; a second Ctrl-C exits at once
